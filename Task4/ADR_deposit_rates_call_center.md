| UC1 | Оператор кол-центра (внутренний) | Просмотр актуальных ставок | Оператор открывает интерфейс кол-центра → запрашивает текущие ставки → получает актуальные ставки из локальной БД системы кол-центра |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
|**№**|**Требование**|
| :-: | :- |                                                                                                    
| 1 | Актуальность: обновление ставок должно происходить не реже, чем каждые 15 минут |
| 2 | Консистентность: источник правды — АБС. Экспорты должны базироваться на данных из АБС и иметь версионность/штамп времени |
| 3 | Надёжность: доставка файлов/сообщений гарантирована |
| 4 | Безопасность: передача файлов/сообщений должна быть зашифрована; для внешнего партнёра — защищённый канал (S3 presigned URL) |
| 5 | Совместимость: формат файлов для партнёра — CSV/JSON с заранее согласованной схемой; поддержка импорта в платформу партнёра |
| 6 | Производительность: получение ставок в кол-центре должно занимать < 200 ms (из кэша/локального БД) |
| 7 | Отказоустойчивость: если доставка/обновление не прошло — операторы видят последний доступный набор ставок с пометкой |
| 8 | Минимизация изменений в ядре: по возможности изменения делаются через интеграционный слой (middleware), а не правки в АБС |

### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграммы контекста и контейнеров в модели C4:
- context_diagram.puml
- container_diagram.puml

Источник правды — АБС. Разрабатываем компонент "Rate Exporter" (внутри банка), который формирует выдержанный, валидный файл (CSV/JSON) и публикует в файловое хранилище (S3). Для внутреннего кол-центра предусмотрен адаптер в их системе REST-пулл от хранилища обновляющий локальную БД ставок. Для партнёра делаем инкрементный файл и выкладку в защищённое хранилище (pre-signed S3 URL).

Для обеспечения доступности актуальных ставок сотрудникам внутреннего и партнёрского колл-центра предлагается централизованная модель выгрузки ставок в единое хранилище S3 так как:
- оно позволяет отдавать файлы как внутренним, так и внешним потребителям
- упрощает MVP
- соответствует нефункциональным требованиям по простоте и низкой стоимости

Причины выбора этой архитектуры
- Минимальные изменения в ABS
- Rate Exporter можно реализовать силами команды банка без вмешательства подрядчика
- Внутренний колл-центр может обновлять ставки регулярно без сложных интеграций
- Партнёрский колл-центр не позволяет API-вызовы, значит файлы — единственный подходящий вариант
- MVP ориентирован на быстрый запуск маркетинга — решение максимально простое

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

Альтернатива 1 — прямой API-эндоинт для системы колл-центров в IB/ABS
Минусы:
ухудшается безопасность решения
партнёрский колл-центр не может вызывать API
выше стоимость разработки
нужен SLA и нагрузочное тестирование API

Альтернатива 2 — Event-driven модель (Kafka, MQ)
Минусы:
партнёр всё равно не сможет принимать события
существенно увеличивает сложность MVP

Альтернатива 3 — Прямая интеграция ABS → колл-центр
Минусы:
дорогая интеграция Java → система CC
увеличивает нагрузку на ABS
тяжёлое решение для MVP

**Недостатки, ограничения, риски**
* Отсутствие оповещений об изменении ставок: внутренний колл-центр может видеть данные с задержкой до периода cron-запуска
* Ручной процесс для партнёра: возможен человеческий фактор, неправильные версии файлов
* Rate Exporter становится критическим компонентом: при его падении будет распространяться устаревшая версия ставок
* Данные в S3 должны быть защищены: риск утечки чувствительной информации
* Нужна четкие договорённости с партнёром по формату и частоте файлов
* Если АБС медленна или перегружена, экспорт может быть тяжёлым — требуется throttling и incremental export
* Требуется безопасное хранилище и управление доступом (presigned links, expiring URLs)


### **Список крупных задач по системам**

**ABS**
* Предоставление актуальных депозитных ставок
- API для чтения ставок для Rate Exporter
- Обеспечение целостности и актуальности данных
* Интеграция с Rate Exporter
- Обеспечить стабильное чтение ставок с учетом нагрузки
- Логирование и мониторинг вызовов API
- Поддержка корректного формата данных для экспорта

**Rate Exporter (Сервис экспорта ставок)**
* Чтение данных из АБС
- Планировщик (Scheduler) для периодического запроса ставок
- Обработка ошибок и повторные попытки
* Генерация файлов
- Форматы CSV / JSON для внутреннего и внешнего использования
- Валидация данных перед выгрузкой
* Выгрузка в S3
- Надежное сохранение файлов
- Управление версиями файлов для колл-центров
* Мониторинг и алерты
- Проверка успешной генерации и загрузки файлов
- Логирование операций

**S3 Хранилище**
* Хранение файлов ставок
- Настройка структуры папок / версий файлов
- Контроль доступа для внутренних и партнёрских систем
* Доступ к файлам
- Установить права доступа для Cron-загрузки внутреннего колл-центра
- Обеспечить доступ партнёрского колл-центра для ручного скачивания

**Внутренний Колл-центр (Internal Call Center)**
* CallCenter Backend
- Реализовать Cron-пулл для загрузки файлов из S3
- Обновление локальной базы данных (PostgreSQL)
- Обработка ошибок при загрузке файлов (fallback на предыдущую версию)
* CallCenter Database
- Хранение актуальных ставок
- Обеспечение целостности и производительности при обновлениях
* CallCenter UI
- Запрос ставок через Backend API
- Отображение актуальной информации для операторов
- Обеспечить удобный интерфейс для быстрого поиска ставок

**Партнёрский Колл-центр (Partner Call Center)**
* Доступ к актуальным ставкам
- Настроить процесс ручного скачивания файлов из S3
- Инструкции для сотрудников партнёрского колл-центра
* Обеспечение безопасности
- Контроль доступа к S3
- Версионирование файлов для корректного использования
